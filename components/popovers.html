Popovers

Accessible popover patterns with keyboard triggering, focus management, and dismissal behavior.

Design guidelines

UX guidelines

  • Include a visible close button inside the popover — do not rely solely on clicking outside or pressing Escape, as both require the user to know that mechanism exists.
  • If the popover contains only read-only information (no interactive elements), consider using the Tooltips pattern instead — see the Tooltips page for the distinction.
  • Popover content should be concise — for complex tasks requiring more space, consider a modal or a dedicated page instead.

Visual design guidelines

  • The popover should be visually anchored to its trigger with an arrow or caret so the relationship between the trigger and the popover is immediately clear.
  • Allow sufficient padding around popover content to prevent text from touching the edges and to provide adequate touch targets for interactive elements inside.
  • The popover must appear at a z-index above all other page content and must not extend beyond the viewport — position it so it flips to the other side of the trigger if it would clip the edge.
  • Interactive elements inside the popover must have adequate touch targets (minimum 44×44 px) and clearly visible focus rings.

Dev guidelines for web

  • The trigger must be a <button> with aria-expanded="false" when closed and aria-expanded="true" when open. Use aria-controls pointing to the popover's id: <button aria-expanded="false" aria-controls="popover-options">Options</button>.
  • If the popover contains interactive content, give it role="dialog" with an appropriate aria-label or aria-labeledby. If it is purely informational (no interactive elements), role="tooltip" and aria-describedby on the trigger may be more appropriate — see the Tooltips page.
  • Move focus into the popover on open when it contains interactive content — to the container (tabindex="-1") or the first focusable element. Users who cannot see the popover must have focus inside it to know it exists.
  • Support Escape to close the popover. When Escape is pressed while focus is inside, close the popover and return focus to the trigger.
  • Return focus to the trigger on close regardless of the close mechanism — Escape, the close button, or clicking outside. Never leave focus inside a closed overlay.
  • If the popover does not use role="dialog", ensure that tabbing out of it also closes it, so it does not remain open and obscure content behind it.

Example code

<button
  type="button"
  id="filter-btn"
  aria-haspopup="dialog"
  aria-expanded="false"
  aria-controls="filter-popover"
>
  Filters
</button>

<div
  id="filter-popover"
  role="dialog"
  aria-labelledby="filter-heading"
  aria-modal="false"
  hidden
>
  <h3 id="filter-heading">Filter results</h3>
  <form>
    <label>
      <input type="checkbox" name="in-stock" />
      In stock only
    </label>
    <button type="submit">Apply filters</button>
  </form>
  <button
    type="button"
    aria-label="Close filters popover"
  >
    &#10005;
  </button>
</div>

Dev guidelines for iOS

  • Wrap the popover trigger button and its associated popover content in a parent view using .accessibilityElement(children: .contain) so VoiceOver treats the trigger and popover as separate, independently focusable elements rather than merging them into a single announcement.
  • Apply .accessibilityLabel("Filters") and .accessibilityHint("Opens a popover with filter options") to the trigger button so VoiceOver users understand both what the control is and what activating it will do before they act.
  • When the popover opens, post a UIAccessibility.post(notification: .screenChanged, argument: popoverHeadingView) announcement to move VoiceOver focus into the popover — equivalent to programmatic focus management on web. Use .announcement for lightweight state changes and .screenChanged when the majority of the screen content has changed.
  • Add .accessibilityAddTraits(.isButton) to the trigger and ensure the close button inside the popover has .accessibilityLabel("Close filters popover") so its purpose is unambiguous when no visible label text is present.
  • When the popover is dismissed — by the close button or a tap outside — post UIAccessibility.post(notification: .screenChanged, argument: triggerButton) to return VoiceOver focus to the trigger, matching the web requirement to never leave focus inside a closed overlay.

Example code

struct FilterPopoverButton: View {
    @State private var isPopoverPresented = false

    var body: some View {
        Button {
            isPopoverPresented = true
        } label: {
            Text("Filters")
        }
        .accessibilityLabel("Filters")
        .accessibilityHint("Opens a popover with filter options")
        .accessibilityAddTraits(.isButton)
        .popover(isPresented: $isPopoverPresented) {
            FilterPopoverContent(isPresented: $isPopoverPresented)
        }
    }
}

struct FilterPopoverContent: View {
    @Binding var isPresented: Bool
    @State private var inStockOnly = false

    var body: some View {
        VStack(alignment: .leading, spacing: 16) {
            HStack {
                Text("Filter results")
                    .font(.headline)
                    .accessibilityAddTraits(.isHeader)
                Spacer()
                Button {
                    isPresented = false
                } label: {
                    Image(systemName: "xmark")
                }
                .accessibilityLabel("Close filters popover")
            }
            Toggle("In stock only", isOn: $inStockOnly)
            Button("Apply filters") {
                isPresented = false
            }
            .accessibilityHint("Applies selected filters and closes the popover")
        }
        .padding()
        .accessibilityElement(children: .contain)
    }
}

Dev guidelines for Android

  • Apply Modifier.semantics { contentDescription = "Filters" } and role = Role.Button to the trigger so TalkBack announces it correctly. Without an explicit role, a custom composable may not be identified as interactive.
  • Use mergeDescendants = true on the popover container's semantics block if the popover header and body should be read as a single focusable unit on first entry — or omit it to keep each element individually focusable when the popover contains interactive controls.
  • Add a customActions entry for the close action so TalkBack users can dismiss the popover without having to navigate to the close button: customActions = listOf(CustomAccessibilityAction("Close popover") { onDismiss(); true }).
  • When the popover opens, ensure the first element inside receives focus by using FocusRequester — this mirrors the web requirement to move focus into the popover on open so screen reader users are not left on the trigger with no indication the popover appeared.

Example code

@Composable
fun FilterPopoverButton() {
    var showPopover by remember { mutableStateOf(false) }

    Box {
        Button(
            onClick = { showPopover = true },
            modifier = Modifier.semantics {
                contentDescription = "Filters"
                role = Role.Button
            }
        ) {
            Text("Filters")
        }

        if (showPopover) {
            FilterPopoverContent(onDismiss = { showPopover = false })
        }
    }
}

@Composable
fun FilterPopoverContent(onDismiss: () -> Unit) {
    val focusRequester = remember { FocusRequester() }
    var inStockOnly by remember { mutableStateOf(false) }

    Surface(
        shape = MaterialTheme.shapes.medium,
        tonalElevation = 4.dp,
        modifier = Modifier
            .semantics {
                customActions = listOf(
                    CustomAccessibilityAction("Close popover") { onDismiss(); true }
                )
            }
    ) {
        Column(modifier = Modifier.padding(16.dp)) {
            Row(
                horizontalArrangement = Arrangement.SpaceBetween,
                modifier = Modifier.fillMaxWidth()
            ) {
                Text(
                    text = "Filter results",
                    style = MaterialTheme.typography.titleMedium,
                    modifier = Modifier
                        .focusRequester(focusRequester)
                        .semantics { heading() }
                )
                IconButton(
                    onClick = onDismiss,
                    modifier = Modifier.semantics {
                        contentDescription = "Close filters popover"
                    }
                ) {
                    Icon(Icons.Default.Close, contentDescription = null)
                }
            }
            Row(verticalAlignment = Alignment.CenterVertically) {
                Checkbox(checked = inStockOnly, onCheckedChange = { inStockOnly = it })
                Text("In stock only")
            }
            Button(onClick = onDismiss, modifier = Modifier.fillMaxWidth()) {
                Text("Apply filters")
            }
        }
    }

    LaunchedEffect(Unit) { focusRequester.requestFocus() }
}
