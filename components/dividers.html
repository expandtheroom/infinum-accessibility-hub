Dividers & Separators

Accessible divider and separator patterns using correct semantic HTML.

Design guidelines

UX guidelines

  • Never use a divider where a heading would communicate structure better; a heading creates navigable structure, a divider does not.
  • Use whitespace as the primary separator between sections — reserve visible dividers for meaningful content boundaries only.
  • Do not place a divider between every list item; reserve them for breaks between distinct groups or sections of content.

Visual design guidelines

  • Decorative dividers should be thin and low-contrast — a subtle visual cue, not a dominant element that draws the eye away from content.
  • Maintain consistent spacing above and below every divider so the visual rhythm is predictable across the page.
  • Vertical separators in toolbars or navigation bars must have sufficient contrast against the surrounding background to be perceivable by low-vision users.

Dev guidelines for web

  • Decorative <hr> elements must have role="presentation" or aria-hidden="true" to prevent screen readers from announcing a meaningless "separator" interruption.
  • Semantic separators inside menus, listboxes, or toolbars use role="separator" on a <li> — this signals a group boundary to assistive technologies without being a focusable or selectable item.
  • Vertical separators must carry aria-orientation="vertical" so assistive technologies convey the correct orientation; the default is horizontal.
  • Never place a native <hr> directly inside <ul> or <ol> — use <li role="separator"> instead to maintain valid list structure.
  • Do not rely on dividers to create content structure that should come from headings (<h2>–<h6>) and ARIA landmark regions (<section>, <nav>, <aside>).
  • CSS-generated decorative lines via ::before / ::after are automatically ignored by screen readers and require no additional ARIA treatment.

Example code

<!-- Semantic separator between content sections -->
<section aria-labelledby="section-a">
  <h2 id="section-a">Published articles</h2>
  <p>Content here.</p>
</section>

<hr />

<section aria-labelledby="section-b">
  <h2 id="section-b">Draft articles</h2>
  <p>Content here.</p>
</section>

<!-- Decorative divider: hide from assistive technology -->
<div aria-hidden="true" class="decorative-rule"></div>

Published articles

3 articles are live and visible to readers.

Draft articles

2 drafts are saved but not yet published.

↑ Decorative divider above is aria-hidden="true"

Dev guidelines for iOS

  • Decorative dividers rendered as plain Rectangle or Divider views must have .accessibilityHidden(true) applied so VoiceOver skips them entirely — they carry no meaning for screen reader users.
  • Never rely on a visual divider to communicate section structure; use .accessibilityAddTraits(.isHeader) on the heading view above the content group so VoiceOver users can navigate by headings.
  • When a Divider sits inside a container that groups related content, apply .accessibilityElement(children: .contain) on the container so VoiceOver navigates each child independently rather than merging them across the visual boundary.
  • Vertical separators in toolbars or segmented controls that are purely decorative should also carry .accessibilityHidden(true); any interactive element they visually separate should have its own .accessibilityLabel that makes the grouping clear without reference to the divider.

Example code

import SwiftUI

struct ArticleSectionList: View {
    var body: some View {
        VStack(alignment: .leading, spacing: 0) {
            Text("Published articles")
                .font(.headline)
                .accessibilityAddTraits(.isHeader)
            Text("3 articles are live and visible to readers.")
                .font(.subheadline)
                .padding(.bottom, 12)

            // Semantic divider — hidden from VoiceOver
            Divider()
                .accessibilityHidden(true)
                .padding(.vertical, 8)

            Text("Draft articles")
                .font(.headline)
                .accessibilityAddTraits(.isHeader)
            Text("2 drafts are saved but not yet published.")
                .font(.subheadline)
                .padding(.bottom, 12)

            // Decorative gradient rule — hidden from VoiceOver
            Rectangle()
                .fill(
                    LinearGradient(
                        colors: [Color.blue, Color.clear],
                        startPoint: .leading,
                        endPoint: .trailing
                    )
                )
                .frame(height: 2)
                .accessibilityHidden(true)
        }
        .padding()
    }
}

Dev guidelines for Android

  • Decorative HorizontalDivider and VerticalDivider composables are not focusable by default, but if wrapped in a container that merges semantics, use Modifier.semantics { invisibleToUser() } or Modifier.clearAndSetSemantics {} to ensure TalkBack never announces them.
  • Do not use a divider to imply section structure that assistive technology cannot perceive; mark the heading above each content group with Modifier.semantics { heading() } so TalkBack users can navigate by swipe-by-heading.
  • When a divider sits inside a parent container, ensure the container does not use mergeDescendants = true across the divider boundary — merging content from both sides of a separator into a single focusable node produces a confusing, combined announcement.
  • Vertical separators in toolbars or tab bars that are purely decorative should be wrapped in a Box with Modifier.semantics(mergeDescendants = false) {} so they remain invisible to TalkBack without suppressing the semantics of adjacent interactive elements.

Example code

import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.semantics.*
import androidx.compose.ui.unit.dp

@Composable
fun ArticleSectionList() {
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = "Published articles",
            style = MaterialTheme.typography.titleMedium,
            modifier = Modifier.semantics { heading() }
        )
        Text(
            text = "3 articles are live and visible to readers.",
            style = MaterialTheme.typography.bodyMedium
        )
        Spacer(modifier = Modifier.height(12.dp))

        // Decorative divider — cleared of semantics so TalkBack skips it
        HorizontalDivider(
            modifier = Modifier.clearAndSetSemantics {}
        )

        Spacer(modifier = Modifier.height(12.dp))
        Text(
            text = "Draft articles",
            style = MaterialTheme.typography.titleMedium,
            modifier = Modifier.semantics { heading() }
        )
        Text(
            text = "2 drafts are saved but not yet published.",
            style = MaterialTheme.typography.bodyMedium
        )
    }
}
