Accordions

Accessible accordion patterns with correct ARIA expanded states and keyboard navigation.

Design guidelines

UX guidelines

  • Make the accordion trigger visually look like a button. Do not style the trigger as plain text or a heading alone. It must be visually distinguishable as an interactive control — with a background, border, or clear affordance — so users know it can be clicked or tapped.
  • Where possible, design panels so fully expanded content is visible without additional scroll. Long panels that require scrolling within them are confusing. If panel content is very long, consider whether the accordion is the right pattern.

Visual design guidelines

  • Use a chevron icon to indicate expand/collapse state. The chevron should point down when the panel is collapsed and rotate to point up when it is open. This provides a clear visual indicator of state at a glance.
  • Mark the chevron icon as aria-hidden. The icon is a visual affordance only. Its state is communicated programmatically via aria-expanded on the button, so the icon itself should be hidden from assistive technology to avoid redundant announcements.
  • Use panel borders or shadows to visually connect the open panel to its trigger. A continuous visual boundary helps users understand which trigger controls which content, reducing cognitive effort.
  • Respect prefers-reduced-motion for the expand/collapse animation. If the panel uses a height or opacity transition, disable or reduce the motion when the user has indicated they prefer less animation.

Dev guidelines for web

  • The trigger must be a <button> nested inside a heading: <h3><button aria-expanded="false" aria-controls="panel-id">…</button></h3>. The heading maintains document outline for users who navigate by headings; the button ensures the trigger is keyboard-focusable and announced as interactive.
  • The panel element must have an id, role="region", and aria-labeledby pointing to the button's id. This creates an explicit programmatic relationship between trigger and content that some screen readers expose as a shortcut.
  • Toggle aria-expanded="true" / aria-expanded="false" on the button via JavaScript. Screen readers announce this as "expanded" or "collapsed" when the button receives focus, communicating state without relying on visual cues alone.
  • Hide collapsed panels using the hidden attribute or display: none — not visibility: hidden. visibility: hidden hides the panel visually but may leave interactive elements within it in the tab order, causing users to focus elements they cannot see.
  • Keyboard: Enter or Space toggles the panel; Tab moves into open panel content sequentially. Focus must stay on the trigger button when a panel opens or closes — do not move it automatically.

Example code

<div>
  <h3>
    <button
      type="button"
      aria-expanded="false"
      aria-controls="accordion-panel-1"
      id="accordion-btn-1"
    >
      What is WCAG?
    </button>
  </h3>
  <div
    id="accordion-panel-1"
    role="region"
    aria-labelledby="accordion-btn-1"
    hidden
  >
    <p>WCAG (Web Content Accessibility Guidelines) is a set of
    internationally recognized standards for making web content
    accessible to people with disabilities.</p>
  </div>
</div>

WCAG (Web Content Accessibility Guidelines) is a set of internationally recognized standards for making web content accessible to people with disabilities.

Dev guidelines for iOS

  • Use .accessibilityElement(children: .combine) on the accordion row container. This merges the trigger label and chevron icon into a single VoiceOver element, so the user hears one announcement per row rather than navigating through two separate elements.
  • Apply .accessibilityLabel("Section title") and .accessibilityHint("Double tap to expand") or "Double tap to collapse" to the trigger button. The label provides the VoiceOver name; the hint communicates what will happen on activation, matching the information that aria-expanded conveys on web.
  • Set .accessibilityValue("expanded") or .accessibilityValue("collapsed") based on the open state. This communicates the current state of the panel to VoiceOver in the same way aria-expanded does, without burying it in the hint.
  • Mark the chevron icon as .accessibilityHidden(true). The icon is a visual affordance only. Its direction communicates state visually, but with .accessibilityValue handling state programmatically, the icon adds no information and creates duplicate announcements.
  • Add .accessibilityAddTraits(.isButton) on the trigger view if it is not a native Button. This ensures VoiceOver announces "button" and users know the element is interactive.

Example code

import SwiftUI

struct AccordionRow: View {
    let title: String
    let content: String
    @State private var isExpanded: Bool = false

    var body: some View {
        VStack(alignment: .leading, spacing: 0) {
            Button(action: { isExpanded.toggle() }) {
                HStack {
                    Text(title)
                        .font(.headline)
                        .foregroundColor(.primary)
                    Spacer()
                    Image(systemName: isExpanded ? "chevron.up" : "chevron.down")
                        .accessibilityHidden(true)
                }
                .padding()
            }
            .accessibilityLabel(title)
            .accessibilityHint(isExpanded ? "Double tap to collapse" : "Double tap to expand")
            .accessibilityValue(isExpanded ? "expanded" : "collapsed")
            .accessibilityAddTraits(.isButton)

            if isExpanded {
                Text(content)
                    .padding()
                    .accessibilityElement(children: .contain)
            }
        }
        .background(Color(.systemBackground))
        .overlay(
            RoundedRectangle(cornerRadius: 8)
                .stroke(Color(.separator), lineWidth: 1)
        )
    }
}

Dev guidelines for Android

  • Use Modifier.semantics { contentDescription = "..." } on the trigger row to give TalkBack a clear, combined announcement. Without this, TalkBack may read the chevron icon text separately from the label, producing confusing announcements.
  • Set stateDescription = if (isExpanded) "Expanded" else "Collapsed" inside the semantics block. TalkBack appends this to the content description, communicating state the same way aria-expanded does on web.
  • Apply role = Role.Button in the semantics block on any custom trigger that is not a native Button composable. TalkBack announces "button" after the label so users know the element is interactive.
  • Use Modifier.clearAndSetSemantics { } on the chevron icon to suppress its TalkBack announcement. The icon provides a visual affordance only; state is already communicated via stateDescription, so the icon should not produce an additional focus stop.

Example code

import androidx.compose.foundation.clickable
import androidx.compose.foundation.layout.*
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.KeyboardArrowDown
import androidx.compose.material.icons.filled.KeyboardArrowUp
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.semantics.*
import androidx.compose.ui.unit.dp

@Composable
fun AccordionRow(title: String, content: String) {
    var isExpanded by remember { mutableStateOf(false) }

    Column {
        Row(
            modifier = Modifier
                .fillMaxWidth()
                .clickable { isExpanded = !isExpanded }
                .semantics {
                    contentDescription = title
                    stateDescription = if (isExpanded) "Expanded" else "Collapsed"
                    role = Role.Button
                }
                .padding(16.dp),
            horizontalArrangement = Arrangement.SpaceBetween,
            verticalAlignment = Alignment.CenterVertically
        ) {
            Text(text = title, style = MaterialTheme.typography.titleMedium)
            Icon(
                imageVector = if (isExpanded) Icons.Default.KeyboardArrowUp
                              else Icons.Default.KeyboardArrowDown,
                contentDescription = null,
                modifier = Modifier.clearAndSetSemantics { }
            )
        }
        if (isExpanded) {
            Text(
                text = content,
                modifier = Modifier.padding(horizontal = 16.dp, vertical = 8.dp),
                style = MaterialTheme.typography.bodyMedium
            )
        }
    }
}
