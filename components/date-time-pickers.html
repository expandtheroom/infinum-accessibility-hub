Date & Time Pickers

Accessible date and time input patterns that work for keyboard users, screen readers, and people with cognitive disabilities.

Design guidelines

UX guidelines

  • Include the date format as a visible hint in the label or in hint text directly below the input — never in placeholder text alone. For example: "Date of birth (DD/MM/YYYY)". Placeholder text disappears when the user starts typing and is insufficient as the only format guide.
  • Error messages must be specific and actionable — write "Date must be today or in the future" rather than "Invalid date". Design error states to appear below the input with a color change plus an error icon, never color alone.
  • The calendar or time popup must be triggered by a clearly labeled button — typically a calendar icon button adjacent to the input. Annotate the button's accessible name in design files (e.g. "Choose date") so developers expose it correctly.
  • Avoid custom date pickers unless native inputs are insufficient — document the business reason in your design files. Custom calendar widgets carry significant accessibility risk and require extensive ARIA and keyboard implementation to match the native browser experience.

Visual design guidelines

  • The selected date must be visually distinct with accessible contrast — the selected day cell should meet a minimum 3:1 contrast ratio against adjacent unselected cells, not just against the page background. Avoid using only a subtle background fill that may not be distinguishable by users with low vision.
  • Today's date must be visually distinct from the selected date — use different styling (e.g. a border for today, a filled background for selected) so the two states are not confused by users with color blindness or low vision.
  • Disabled dates must look non-interactive — use reduced opacity, a strikethrough, or a visually muted color paired with a not-allowed cursor. Annotate in design files that disabled dates must also be communicated programmatically, not just styled.

Dev guidelines for web

  • Prefer <input type="date"> and <input type="time"> — browsers provide accessible, keyboard-operable date pickers at no implementation cost. Associate a visible <label> via for/id and link hint text via aria-describedby.
  • Link format hint text to the input: <input type="date" id="dob" aria-describedby="dob-hint" /> with <p id="dob-hint">Format: DD/MM/YYYY</p>. Screen readers announce the hint after the label when the field receives focus.
  • On validation failure, set aria-invalid="true" on the input and add the error message element's id to aria-describedby. Describe the failure specifically: "Date must be today or in the future".
  • If a custom calendar widget is required, implement the full ARIA grid pattern: role="grid" on the calendar, role="row" on each week row, and role="gridcell" on each day. Apply aria-selected="true" to the selected day and aria-disabled="true" to unavailable dates.
  • Keyboard navigation in a custom calendar grid: Arrow Left/Arrow Right move one day, Arrow Up/Arrow Down move one week, Page Up/Page Down move one month, Home/End jump to the first/last day of the week, Enter or Space select, Escape closes the dialog and returns focus to the trigger.
  • Use aria-label on each day cell to provide a full, unambiguous date — e.g. aria-label="14 March 2026" rather than just "14" — so screen reader users hear the complete date regardless of the visual calendar layout.
  • The calendar trigger button must have a descriptive label such as aria-label="Choose date". When the dialog opens, move focus into it. When it closes (via selection or Escape), return focus to the trigger button.

Example code

<div>
  <label for="appointment-date">
    Appointment date
    <span aria-hidden="true">*</span>
    <span class="visually-hidden">(required)</span>
  </label>
  <input
    type="date"
    id="appointment-date"
    name="appointment-date"
    required
    aria-describedby="date-hint"
    min="2025-01-01"
    max="2026-12-31"
  />
  <p id="date-hint">
    Select a date between January 2025 and December 2026.
  </p>
</div>

Select a date between January 2025 and December 2026.

Dev guidelines for iOS

  • Prefer DatePicker with a descriptive label — SwiftUI's native DatePicker is fully VoiceOver accessible. Pass a visible label string as the first argument; it becomes the accessibility label for the control. Use .labelsHidden() only when a separate visible label is already present, and in that case set .accessibilityLabel("...") explicitly on the picker.
  • Announce the selected value with .accessibilityValue("...") — when using a custom date wheel or a read-only display that reflects the picker's value, set .accessibilityValue to a human-readable string (e.g. "15 March 2026") so VoiceOver reads the current selection without requiring the user to navigate into the picker.
  • Use .accessibilityHint("...") to explain the picker's purpose — for pickers with date range constraints (e.g. future dates only), add a hint such as "Double-tap to open. Only future dates are available." This is distinct from the label and helps users understand constraints before interacting.
  • Set .accessibilityElement(children: .combine) on grouped date + time fields — if a date and a time picker are visually grouped under a single label, wrap them in a container view and apply .accessibilityElement(children: .combine) so VoiceOver treats the group as a single focusable unit with a combined accessible name and value.
  • Use UIAccessibility.post(notification: .announcement, argument: "...") after programmatic date changes — if the app pre-fills or auto-advances the date (e.g. skipping unavailable dates), post an announcement so VoiceOver users are informed of the new value without having to re-focus the picker.

Example code

import SwiftUI

struct AppointmentDatePicker: View {
    @State private var selectedDate = Date()

    private var dateRange: ClosedRange<Date> {
        let start = Date()
        let end = Calendar.current.date(byAdding: .year, value: 1, to: start)!
        return start...end
    }

    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            Text("Appointment date")
                .font(.headline)

            DatePicker(
                "Appointment date",
                selection: $selectedDate,
                in: dateRange,
                displayedComponents: .date
            )
            .labelsHidden()
            .accessibilityLabel("Appointment date")
            .accessibilityValue(
                selectedDate.formatted(date: .long, time: .omitted)
            )
            .accessibilityHint("Double-tap to open. Only dates within the next year are available.")
        }
        .padding()
    }
}

Dev guidelines for Android

  • Use Material3 DatePicker or DatePickerDialog — these components include built-in TalkBack support. Avoid fully custom calendar grids unless the native component cannot meet the requirement; custom implementations require careful manual semantics work.
  • Set contentDescription on the trigger button — if you use an icon button to open the date picker dialog, apply Modifier.semantics { contentDescription = "Choose appointment date" } so TalkBack announces a meaningful label rather than the icon's default or nothing.
  • Apply stateDescription to reflect the current selection — on a read-only text field or surface that displays the chosen date, add Modifier.semantics { stateDescription = formattedDate } so TalkBack announces the selected value as part of the element's state, not just its label.
  • Use mergeDescendants = true for label + field groupings — if a date label and its associated picker trigger or text display are separate composables, wrap them in a Box or Column with Modifier.semantics(mergeDescendants = true) {} so TalkBack focuses the group as a single item with a combined announcement.

Example code

import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.semantics.*

@Composable
fun AppointmentDateField(
    selectedDateMillis: Long?,
    onPickerOpen: () -> Unit
) {
    val formattedDate = selectedDateMillis
        ?.let { millis -> formatDate(millis) }
        ?: "No date selected"

    Column(
        modifier = Modifier.semantics(mergeDescendants = true) {}
    ) {
        Text(text = "Appointment date", style = MaterialTheme.typography.labelLarge)

        OutlinedTextField(
            value = formattedDate,
            onValueChange = {},
            readOnly = true,
            modifier = Modifier.semantics {
                stateDescription = formattedDate
                contentDescription = "Appointment date, $formattedDate"
            },
            trailingIcon = {
                IconButton(
                    onClick = onPickerOpen,
                    modifier = Modifier.semantics {
                        contentDescription = "Choose appointment date"
                    }
                ) {
                    Icon(Icons.Default.DateRange, contentDescription = null)
                }
            }
        )
    }
}
