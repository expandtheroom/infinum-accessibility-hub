File Upload Fields

Accessible file upload patterns that work for all users, including keyboard users and those using assistive technologies.

Design guidelines

UX guidelines

  • State accepted file types and size limits in the label or hint text — never leave users to discover restrictions through error messages after a failed upload. Display this information visibly below the label at all times: e.g. "Accepted: PDF, DOCX. Maximum: 5MB."
  • A fallback button must always be visible alongside any drag-and-drop zone — label it "Choose file" or "Browse files". Never provide drag-and-drop as the only upload method. The button must be prominently placed, not hidden below the fold or styled as a secondary action.
  • Annotate upload states in design files: default, drag-hover (file is being dragged over the zone), uploading, success, and error. Each state must be designed and handed off explicitly so developers know what to implement for each transition.

Visual design guidelines

  • Design a visible progress indicator for uploads that take time — a progress bar with a percentage or animated indicator, plus a text status such as "Uploading… 60%". Progress must not rely on color or animation alone to convey state.
  • Error states must combine color with a secondary indicator — a red border plus an error icon and a descriptive message. Write specific errors: "File too large: your file is 8MB, the limit is 5MB" rather than just "Upload failed".
  • Success states must confirm the file name — after upload, display the selected or uploaded filename visibly so users can verify the correct file was chosen. Add a success icon and confirmation message alongside it.
  • Drag-and-drop zones must have a clearly visible boundary — use a dashed or solid border with sufficient contrast (3:1 minimum against the page background) and a label inside the zone describing the action: "Drag files here or…"

Dev guidelines for web

  • Use <input type="file"> with an associated <label> via for/id. The native element opens the file browser dialog when activated by keyboard or pointer. Use the accept attribute to restrict file types: e.g. accept=".pdf,.docx".
  • Link format and size hints via aria-describedby: <input type="file" id="cv" aria-describedby="cv-hint" /> with <p id="cv-hint">Accepted: PDF, DOCX. Maximum: 5MB.</p>. Screen readers announce the hint after the label when the field receives focus.
  • To create a custom-styled upload button, visually hide the native input using a .visually-hidden CSS class (not display:none or visibility:hidden, which remove it from keyboard access), then trigger it from a styled <button> using inputElement.click(), or use a styled <label for="..."> as the visible trigger.
  • Use the multiple attribute when multi-file upload is supported: <input type="file" multiple />. Communicate this affordance in the hint text and design.
  • On validation failure, set aria-invalid="true" on the input and add the error message's id to aria-describedby. The error must be visible and specific: "File too large: 8MB uploaded, 5MB maximum."
  • For async uploads, announce completion or failure using an aria-live="polite" region: e.g. "profile-photo.jpg uploaded successfully." Move focus to the success/error message if the upload result requires user action.
  • Display the selected filename in visible text adjacent to the input after selection. The native input does not display the filename in a consistently accessible way — add a visible text element that updates via JavaScript with the selected file's name.

Example code

<div>
  <label for="resume-upload">
    Upload your resume
    <span aria-hidden="true">*</span>
    <span class="visually-hidden">(required)</span>
  </label>
  <input
    type="file"
    id="resume-upload"
    name="resume"
    accept=".pdf,.doc,.docx"
    required
    aria-describedby="resume-hint"
  />
  <p id="resume-hint">
    Accepted formats: PDF, DOC, DOCX. Maximum size: 5 MB.
  </p>
</div>

Accepted formats: PDF, DOC, DOCX. Maximum size: 5 MB.

Dev guidelines for iOS

  • Use .accessibilityLabel("...") on the upload button — the native PhotosPicker or custom "Choose file" button should carry a clear VoiceOver label such as "Upload resume, button". Without an explicit label, VoiceOver may announce the button's SF Symbol name or nothing at all.
  • Use .accessibilityHint("...") to describe the outcome — for example, "Opens file browser to select a PDF or DOCX up to 5 MB." Hints provide the context users need before activating the control, helping them avoid unexpected system dialogs.
  • Announce upload progress and completion with UIAccessibility.post(notification: .announcement, argument: "...") — post an announcement when the upload finishes or fails, e.g. "resume.pdf uploaded successfully" or "Upload failed: file exceeds 5 MB." This is the VoiceOver equivalent of an aria-live region.
  • Use .accessibilityValue("...") to convey dynamic upload progress — if you display a progress bar or percentage, set its accessibility value to the current percentage string, e.g. "60 percent", so VoiceOver users hear progress without needing to navigate to a visual indicator.
  • Use .accessibilityElement(children: .combine) on the upload result row — when the uploaded file is shown as a row containing a filename, file-type icon, and a remove button, combine the filename and icon into one focusable unit so VoiceOver announces them together. Keep the remove button as a separate focusable element or use accessibilityCustomActions to attach it.

Example code

import SwiftUI
import PhotosUI

struct FileUploadField: View {
    @State private var selectedItem: PhotosPickerItem? = nil
    @State private var uploadedFileName: String? = nil
    @State private var statusMessage: String = ""

    var body: some View {
        VStack(alignment: .leading, spacing: 12) {
            Text("Upload your resume")
                .font(.headline)

            PhotosPicker(
                selection: $selectedItem,
                matching: .any(of: [.images])
            ) {
                Label("Choose file", systemImage: "paperclip")
            }
            .accessibilityLabel("Choose file")
            .accessibilityHint("Opens file browser to select a PDF or DOCX up to 5 MB")
            .onChange(of: selectedItem) { newItem in
                if newItem != nil {
                    uploadedFileName = "resume.pdf"
                    statusMessage = "resume.pdf uploaded successfully"
                    UIAccessibility.post(
                        notification: .announcement,
                        argument: statusMessage
                    )
                }
            }

            if let fileName = uploadedFileName {
                HStack {
                    Image(systemName: "doc.fill")
                        .accessibilityHidden(true)
                    Text(fileName)
                }
                .accessibilityElement(children: .combine)
                .accessibilityLabel(fileName)
            }

            Text("Accepted: PDF, DOCX. Maximum: 5 MB.")
                .font(.caption)
                .foregroundColor(.secondary)
        }
        .padding()
    }
}

Dev guidelines for Android

  • Set contentDescription on the upload button — use Modifier.semantics { contentDescription = "Choose file, opens file browser" } so TalkBack announces a meaningful label. Without this, TalkBack may read the button text alone, which may lack enough context about the expected file types or size limit.
  • Set role = Role.Button on any custom upload trigger — if you build a custom composable to replace the system file picker button, declare its role explicitly so TalkBack appends "button" to the announcement and users know it is interactive.
  • Use stateDescription to convey upload progress — set Modifier.semantics { stateDescription = "Uploading, 60 percent" } on the progress indicator so TalkBack can read the current state when the user navigates to it, rather than relying on a visual-only bar.
  • Use LiveRegionMode.Polite to announce upload completion or failure — wrap your status text composable in Modifier.semantics { liveRegion = LiveRegionMode.Polite }. When the text changes to "resume.pdf uploaded successfully" or an error message, TalkBack announces the update automatically without requiring the user to navigate there.
  • Use mergeDescendants = true on the uploaded file row — when the uploaded file is displayed as a row with a filename, icon, and remove button, merge the filename and icon into one focusable unit. Keep the remove action as a customActions entry so TalkBack users can trigger it via the local actions menu without cluttering the focus order.

Example code

import androidx.activity.compose.rememberLauncherForActivityResult
import androidx.activity.result.contract.ActivityResultContracts
import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.semantics.*
import androidx.compose.ui.unit.dp

@Composable
fun FileUploadField() {
    var uploadedFileName by remember { mutableStateOf<String?>(null) }
    var statusMessage by remember { mutableStateOf("") }

    val launcher = rememberLauncherForActivityResult(
        contract = ActivityResultContracts.GetContent()
    ) { uri ->
        if (uri != null) {
            uploadedFileName = "resume.pdf"
            statusMessage = "resume.pdf uploaded successfully"
        }
    }

    Column(verticalArrangement = Arrangement.spacedBy(8.dp)) {
        Text("Upload your resume", style = MaterialTheme.typography.titleMedium)

        Button(
            onClick = { launcher.launch("application/pdf") },
            modifier = Modifier.semantics {
                contentDescription = "Choose file, opens file browser"
                role = Role.Button
            }
        ) {
            Text("Choose file")
        }

        Text(
            text = statusMessage,
            modifier = Modifier.semantics {
                liveRegion = LiveRegionMode.Polite
            }
        )

        uploadedFileName?.let { fileName ->
            Row(
                modifier = Modifier.semantics(mergeDescendants = true) {
                    contentDescription = fileName
                    customActions = listOf(
                        CustomAccessibilityAction("Remove file") {
                            uploadedFileName = null
                            true
                        }
                    )
                }
            ) {
                Icon(imageVector = Icons.Default.AttachFile, contentDescription = null)
                Text(fileName)
            }
        }

        Text(
            text = "Accepted: PDF, DOCX. Maximum: 5 MB.",
            style = MaterialTheme.typography.bodySmall
        )
    }
}
