Carousels / Sliders

Accessible carousel and slider patterns with pause controls, keyboard navigation, and live region announcements.

Design guidelines

UX guidelines

  • Include a pause/stop button that is always visible. Autoplay must be user-controllable at any time. The pause button should be the first interactive element inside the carousel region and must never be hidden or clipped.
  • Label prev/next controls with text, not just icons. Provide visible text labels or visually hidden supplementary text — for example "Previous slide" / "Next slide" — so users can distinguish controls from one another at a glance.
  • Show a slide position indicator. Display either dot indicators or a text counter such as "2 of 5" so users always know where they are within the sequence.
  • Autoplay should be off by default. Do not assume users want animation. If autoplay must be on, the minimum dwell time per slide is 5 seconds to give users time to read and respond.
  • Question whether a carousel is the right choice. An image grid, a list of featured cards, or a simple section with a heading often gives users better access to the same content without any accessibility burden.

Visual design guidelines

  • Disable autoplay motion when the user prefers it. Respect prefers-reduced-motion by disabling autoplay transitions entirely — not just slowing them down.

Dev guidelines for web

  • Pause/resume button: use aria-pressed or update aria-label to reflect state. When autoplay is active, the button label should read "Pause slideshow"; when paused, "Play slideshow". Toggling aria-pressed is an alternative pattern for a toggle button.
  • Pause autoplay when keyboard focus enters the carousel. Listen for focusin events on the carousel container and suspend rotation so users are not interrupted mid-interaction.
  • Prev/next controls must be <button> elements with descriptive aria-label values. Both must be reachable by Tab and activated by Enter or Space.
  • Use aria-live="polite" on the slide counter or manage announcements with aria-roledescription="carousel". Each slide should carry role="group" and aria-label="Slide 2 of 5" so screen reader users understand position and context.
  • Remove hidden slides from the tab order and accessibility tree. Use the hidden attribute or display: none on non-active slides — not visibility: hidden alone, which leaves content traversable by keyboard while concealing it visually.
  • Honor prefers-reduced-motion by disabling autoplay in CSS and JavaScript. Use a media query to detect the preference and stop the rotation timer on load if it is set.

Dev guidelines for iOS

  • Combine each slide into a single focusable unit using .accessibilityElement(children: .combine). This merges the slide's image, heading, and body text into one VoiceOver element, preventing fragmented navigation through slide content.
  • Give each slide a descriptive .accessibilityLabel that includes position. For example, .accessibilityLabel("Slide 2 of 5: Intro to WCAG") so VoiceOver users always know where they are in the sequence.
  • Label prev/next buttons with .accessibilityLabel and add an .accessibilityHint. For example, .accessibilityLabel("Next slide") with .accessibilityHint("Advances to slide 3 of 5"). Apply .accessibilityAddTraits(.isButton) if the control is not a native Button.
  • Announce slide changes as a live region using UIAccessibility.post(notification: .announcement, argument:). Post the announcement after updating the active slide so VoiceOver reads out the new position without the user needing to navigate to a counter element.
  • Pause autoplay when VoiceOver is active and respect UIAccessibility.isReduceMotionEnabled. Check both flags on appearance and suspend the rotation timer so animated transitions do not interrupt screen reader users or users who have requested reduced motion.

Example code

import SwiftUI

struct AccessibleCarousel: View {
    let slides: [(title: String, body: String)]
    @State private var currentIndex = 0

    var body: some View {
        VStack(spacing: 16) {
            slideView(for: slides[currentIndex], index: currentIndex)

            HStack(spacing: 24) {
                Button("Previous slide") {
                    currentIndex = (currentIndex - 1 + slides.count) % slides.count
                    announceSlide()
                }
                .accessibilityHint("Goes to slide \(currentIndex == 0 ? slides.count : currentIndex) of \(slides.count)")

                Button("Next slide") {
                    currentIndex = (currentIndex + 1) % slides.count
                    announceSlide()
                }
                .accessibilityHint("Advances to slide \(currentIndex == slides.count - 1 ? 1 : currentIndex + 2) of \(slides.count)")
            }
        }
    }

    func slideView(for slide: (title: String, body: String), index: Int) -> some View {
        VStack(alignment: .leading, spacing: 8) {
            Text(slide.title).font(.headline)
            Text(slide.body).font(.body)
        }
        .accessibilityElement(children: .combine)
        .accessibilityLabel("Slide \(index + 1) of \(slides.count): \(slide.title). \(slide.body)")
    }

    func announceSlide() {
        let message = "Slide \(currentIndex + 1) of \(slides.count): \(slides[currentIndex].title)"
        UIAccessibility.post(notification: .announcement, argument: message)
    }
}

Dev guidelines for Android

  • Use mergeDescendants = true on each slide to merge its children into a single focusable unit. This prevents TalkBack from navigating into the individual text elements of a slide separately, mirroring the behaviour of a combined VoiceOver element on iOS.
  • Set a contentDescription on each slide that includes position. For example, contentDescription = "Slide 2 of 5: Intro to WCAG. An overview of the Web Content Accessibility Guidelines." so TalkBack users always hear their position and the slide content together.
  • Apply role = Role.Button to prev/next controls and provide a clear contentDescription. For example, contentDescription = "Next slide". If the control also needs a state description (e.g. disabled at the last slide), set stateDescription accordingly.
  • Announce slide changes using a LiveRegionMode.Polite semantics node on the slide counter. Update the counter's text whenever the active slide changes; Compose will automatically post a TalkBack announcement without requiring focus to move to the counter.

Example code

import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.semantics.*
import androidx.compose.ui.unit.dp

data class Slide(val title: String, val body: String)

@Composable
fun AccessibleCarousel(slides: List<Slide>) {
    var currentIndex by remember { mutableStateOf(0) }
    val slide = slides[currentIndex]
    val positionText = "Slide ${currentIndex + 1} of ${slides.size}"

    Column(verticalArrangement = Arrangement.spacedBy(16.dp)) {
        Box(
            Modifier.semantics(mergeDescendants = true) {
                contentDescription = "$positionText: ${slide.title}. ${slide.body}"
            }
        ) {
            Column {
                Text(slide.title, style = MaterialTheme.typography.titleMedium)
                Text(slide.body, style = MaterialTheme.typography.bodyMedium)
            }
        }

        Text(
            text = positionText,
            modifier = Modifier.semantics {
                liveRegion = LiveRegionMode.Polite
            }
        )

        Row(horizontalArrangement = Arrangement.spacedBy(24.dp)) {
            Button(
                onClick = { currentIndex = (currentIndex - 1 + slides.size) % slides.size },
                modifier = Modifier.semantics { contentDescription = "Previous slide" }
            ) { Text("Previous") }

            Button(
                onClick = { currentIndex = (currentIndex + 1) % slides.size },
                modifier = Modifier.semantics { contentDescription = "Next slide" }
            ) { Text("Next") }
        }
    }
}
