Search Bars

Accessible search input patterns including labeling, submission behavior, and results announcement.

Design guidelines

UX guidelines

  • Include a search icon inside or immediately adjacent to the input to communicate the field's purpose visually. The icon alone is not sufficient — pair it with a visible or screen-reader-accessible label. The icon itself should be decorative (aria-hidden="true") since the label carries the accessible name.
  • The submit or search button must be clearly labeled — use "Search" as visible text, or a search icon with a tooltip and accessible name. Never provide only an unlabeled icon button as the sole way to trigger a search.
  • Empty results must show a clear message — "No results for [query]" with a suggestion to refine the search. Design this message prominently; do not leave an empty container that looks like a loading failure.
  • Annotate autocomplete in design files — specify the keyboard interactions (arrow keys to navigate, Enter to select, Escape to dismiss) so developers have the expected behavior documented before implementation.

Visual design guidelines

  • A clear button (×) must be visible when the input has a value — it should appear inside the input field on the right, or immediately adjacent. Design it with a minimum 44×44px touch target and an accessible label ("Clear search"). It should disappear when the field is empty to avoid visual clutter.
  • Autocomplete suggestion lists must have sufficient contrast — option text must meet 4.5:1 against the list background. The highlighted (active) suggestion must be visually distinct from unselected options using more than color — use a background fill plus a border, or a change in text weight.
  • Design a visible loading state for async suggestions — an animated spinner or "Searching…" text within the suggestion area. The loading state must not rely on color or animation alone.

Dev guidelines for web

  • Wrap the search input in <form role="search"> — this landmark role allows screen reader users to navigate directly to the search form using landmark navigation shortcuts. Use role="search" on a <form>, not on a <div>, so the native form submission behavior (including Enter key) is preserved.
  • Provide a visible <label> or aria-label on the input — placeholder text is not a sufficient accessible name. A common accessible pattern uses a visually hidden label: <label for="site-search" class="visually-hidden">Search this site</label> paired with a visible placeholder.
  • The clear button must be a <button aria-label="Clear search"> — not a styled <span> or <div>. Show it conditionally when the input has a value and move focus back to the input after clearing.
  • For autocomplete suggestions, implement the ARIA combobox pattern: role="combobox" on the input, aria-expanded="true/false", aria-haspopup="listbox", aria-controls pointing to the suggestion list. The list uses role="listbox"; each suggestion uses role="option". Use aria-activedescendant to track the highlighted suggestion without moving DOM focus from the input.
  • Announce result counts with aria-live="polite": <p aria-live="polite" aria-atomic="true">24 results for "accessible forms"</p>. Update this element after each search. For zero results, include a suggestion: "No results for 'accsible forms'. Did you mean 'accessible forms'?"
  • Manage focus after same-page search submission — move focus to the results heading (e.g. an <h2 tabindex="-1">) or the first result so keyboard and screen reader users are oriented to the updated content.
  • For full-page search result pages, update the page <title> to include the query — e.g. "Search results for 'accessible forms' – Accessibility Hub" — so screen reader users hear the context immediately on page load.

Example code

<search>
  <form role="search" action="/search">
    <label for="site-search">Search the site</label>
    <input
      type="search"
      id="site-search"
      name="q"
      placeholder="e.g. buttons, WCAG, contrast"
      autocomplete="off"
    />
    <button type="submit">
      <span class="visually-hidden">Submit search</span>
      <span aria-hidden="true">&#128269;</span>
    </button>
  </form>
</search>

Dev guidelines for iOS

  • Apply .accessibilityLabel("Search") to the search text field — do not rely on placeholder text as the accessible name. VoiceOver reads placeholder text as a hint only; if the field has no label, users hear "text field" with no context about its purpose.
  • Use UIAccessibility.post(notification: .announcement, argument: "...") to announce result counts — post the announcement after the results list updates, e.g. "24 results for accessible forms". For zero results, include a suggestion in the announcement string: "No results for accsible forms. Did you mean accessible forms?"
  • Give the clear button an explicit .accessibilityLabel("Clear search") — the system SF Symbol "xmark.circle.fill" has no default VoiceOver label in this context. Show the button only when the field has a value and return focus to the search field after it is activated.
  • For autocomplete suggestion lists, use .accessibilityElement(children: .contain) on the suggestions container — this keeps each suggestion as a separate focusable VoiceOver element. Add .accessibilityHint("Double tap to apply this suggestion") to each suggestion row so users understand the action before committing.
  • Mark a loading spinner with .accessibilityLabel("Searching") and .accessibilityAddTraits(.updatesFrequently) — this tells VoiceOver the element changes dynamically so it can manage announcement timing, rather than announcing every frame update.

Example code

import SwiftUI

struct AccessibleSearchBar: View {
    @State private var query = ""
    @State private var results: [String] = []
    @State private var isLoading = false
    @State private var resultAnnouncement = ""

    var body: some View {
        VStack(alignment: .leading, spacing: 12) {
            HStack {
                TextField("e.g. buttons, WCAG, contrast", text: $query)
                    .accessibilityLabel("Search the site")
                    .accessibilityHint("Type to search, then activate the Search button")
                    .submitLabel(.search)
                    .onSubmit { performSearch() }

                if !query.isEmpty {
                    Button {
                        query = ""
                        results = []
                        resultAnnouncement = "Search cleared"
                        UIAccessibility.post(
                            notification: .announcement,
                            argument: resultAnnouncement
                        )
                    } label: {
                        Image(systemName: "xmark.circle.fill")
                            .foregroundColor(.secondary)
                    }
                    .accessibilityLabel("Clear search")
                }

                Button("Search") { performSearch() }
                    .buttonStyle(.borderedProminent)
            }
            .padding()
            .background(Color(.systemBackground))
            .overlay(RoundedRectangle(cornerRadius: 8).stroke(Color.gray.opacity(0.4)))

            if isLoading {
                ProgressView()
                    .accessibilityLabel("Searching")
                    .accessibilityAddTraits(.updatesFrequently)
            }

            List(results, id: \.self) { result in
                Text(result)
                    .accessibilityHint("Double tap to open this result")
            }
            .accessibilityElement(children: .contain)
        }
        .padding()
    }

    private func performSearch() {
        isLoading = true
        // Simulate async search
        DispatchQueue.main.asyncAfter(deadline: .now() + 0.8) {
            results = query.isEmpty ? [] : ["Result for \(query) 1", "Result for \(query) 2"]
            isLoading = false
            let count = results.count
            resultAnnouncement = count == 0
                ? "No results for \(query)"
                : "\(count) results for \(query)"
            UIAccessibility.post(notification: .announcement, argument: resultAnnouncement)
        }
    }
}

Dev guidelines for Android

  • Set Modifier.semantics { contentDescription = "Search the site" } on the search text field — TalkBack reads the content description as the field's accessible name. Do not rely on the placeholder (hint text) alone, as TalkBack announces it inconsistently depending on Android version.
  • Use LiveRegionMode.Polite on the results count container — wrap the result count in a Box with Modifier.semantics { liveRegion = LiveRegionMode.Polite } so TalkBack announces the updated count automatically without moving focus away from the search field.
  • Give the clear button an explicit contentDescription and Role.Button — use Modifier.semantics { role = Role.Button; contentDescription = "Clear search" } on the clear icon. Show the button conditionally when the field is non-empty and return focus to the text field after activation.
  • For autocomplete suggestion lists, use mergeDescendants = false on the list container and apply individual semantics per item — each suggestion should be a separate focusable TalkBack element with a contentDescription and Role.Button so users can navigate the list item by item and understand the action before activating.

Example code

import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.semantics.*

@Composable
fun AccessibleSearchBar() {
    var query by remember { mutableStateOf("") }
    var results by remember { mutableStateOf(listOf<String>()) }
    var resultMessage by remember { mutableStateOf("") }

    Column(modifier = Modifier.padding(16.dp)) {
        OutlinedTextField(
            value = query,
            onValueChange = { query = it },
            placeholder = { Text("e.g. buttons, WCAG, contrast") },
            label = { Text("Search the site") },
            trailingIcon = {
                if (query.isNotEmpty()) {
                    IconButton(
                        onClick = {
                            query = ""
                            results = emptyList()
                            resultMessage = "Search cleared"
                        },
                        modifier = Modifier.semantics {
                            role = Role.Button
                            contentDescription = "Clear search"
                        }
                    ) {
                        Icon(Icons.Default.Clear, contentDescription = null)
                    }
                }
            },
            keyboardOptions = KeyboardOptions(imeAction = ImeAction.Search),
            keyboardActions = KeyboardActions(onSearch = {
                results = if (query.isEmpty()) emptyList()
                    else listOf("Result for $query 1", "Result for $query 2")
                resultMessage = if (results.isEmpty()) "No results for $query"
                    else "${results.size} results for $query"
            }),
            modifier = Modifier
                .fillMaxWidth()
                .semantics { contentDescription = "Search the site" }
        )

        Spacer(modifier = Modifier.height(8.dp))

        // Live region announces result count to TalkBack
        Box(modifier = Modifier.semantics { liveRegion = LiveRegionMode.Polite }) {
            if (resultMessage.isNotEmpty()) {
                Text(text = resultMessage, style = MaterialTheme.typography.bodySmall)
            }
        }

        Spacer(modifier = Modifier.height(8.dp))

        results.forEach { result ->
            TextButton(
                onClick = { /* open result */ },
                modifier = Modifier
                    .fillMaxWidth()
                    .semantics {
                        role = Role.Button
                        contentDescription = result
                    }
            ) {
                Text(result)
            }
        }
    }
}
