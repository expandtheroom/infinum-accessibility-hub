Timelines

Accessible timeline patterns with clear temporal structure and screen reader support.

Design guidelines

UX guidelines

  • Chronological order must be clear from the visual layout — top-to-bottom or left-to-right; do not rely on position alone to imply sequence.
  • Each event must provide sufficient context in its visible content — do not rely on the connector line's position to explain what happened or when.
  • Expandable timeline events must have a clear expand affordance (e.g. a visible toggle button or chevron) — do not hide interactivity behind hover states only.

Visual design guidelines

  • Dates must be prominent and legible — sufficient size and contrast so they are immediately distinguishable from event descriptions.
  • The current or active event must be visually distinct (e.g. highlighted node, stronger color, bold label) — not distinguished by color alone.
  • Connector lines and node dots are decorative — they must not carry meaning not present in the text content of each event.

Dev guidelines for web

  • Use <ol> for chronological timelines — the ordered list announces item count and implies sequence to screen reader users; use <ul> only for thematically ordered (non-chronological) timelines.
  • Wrap each event date in <time datetime="2025-03-01">1 March 2025</time> — the ISO 8601 datetime attribute provides a machine-readable value for assistive technologies and search engines.
  • Decorative connector lines and dot nodes must have aria-hidden="true" (inline SVG or <div>) — CSS-generated ::before/::after content is ignored automatically and needs no ARIA treatment.
  • DOM order must match the visual reading order — never use CSS order or position: absolute to visually reorder events in a way that contradicts the DOM sequence.
  • Expandable events use the accordion pattern: <button aria-expanded="false" aria-controls="panel-id"> inside the <li>; the panel uses hidden to remove it from the accessibility tree when collapsed.
  • Link text in timeline items must be descriptive — include event title and date (e.g. "Beta release — 15 June 2024") — never use "Read more" as standalone link text, which is meaningless out of context for screen reader users navigating by links.

Example code

<section aria-labelledby="timeline-heading">
  <h2 id="timeline-heading">Project history</h2>
  <ol>
    <li>
      <time datetime="2024-03-01">March 2024</time>
      <p>Project kickoff and requirements gathering.</p>
    </li>
    <li>
      <time datetime="2024-06-15">June 2024</time>
      <p>Design system completed and handed off to development.</p>
    </li>
    <li>
      <time datetime="2024-09-30">September 2024</time>
      <p>Accessibility audit: 0 critical issues remaining.</p>
    </li>
  </ol>
</section>

Dev guidelines for iOS

  • Use .accessibilityElement(children: .combine) on each timeline event container to merge the date, title, and description into a single VoiceOver focus target — this prevents users from having to navigate through every sub-element of every event individually.
  • Provide a descriptive .accessibilityLabel("...") that includes both the date and the event description (e.g. "March 2024 — Project kickoff and requirements gathering") — do not rely on VoiceOver's automatic label concatenation, which may read sub-elements in an unhelpful order.
  • Decorative connector lines and dot nodes rendered as SwiftUI views or shapes must have .accessibilityHidden(true) applied — they carry no information beyond what the event text already communicates.
  • If an event item can be expanded to reveal more detail, use .accessibilityAddTraits(.isButton) on the tappable element and provide an .accessibilityHint("Double-tap to expand"); update the .accessibilityValue("Expanded") or .accessibilityValue("Collapsed") to reflect current state dynamically.
  • After navigating to a new screen triggered by a timeline event (e.g. tapping "View details"), post a UIAccessibility.post(notification: .screenChanged, argument: nil) notification so VoiceOver moves focus to the top of the new view rather than leaving the user stranded.

Example code

struct TimelineEventRow: View {
    let date: String
    let description: String
    let isDecorative: Bool = true

    var body: some View {
        HStack(alignment: .top, spacing: 12) {
            VStack {
                Circle()
                    .fill(Color.blue)
                    .frame(width: 12, height: 12)
                    .accessibilityHidden(true)
                Rectangle()
                    .fill(Color.gray.opacity(0.4))
                    .frame(width: 2)
                    .accessibilityHidden(true)
            }
            VStack(alignment: .leading, spacing: 4) {
                Text(date)
                    .font(.caption.weight(.bold))
                    .foregroundColor(.secondary)
                Text(description)
                    .font(.body)
            }
        }
        .accessibilityElement(children: .combine)
        .accessibilityLabel("\(date) — \(description)")
    }
}

Dev guidelines for Android

  • Apply Modifier.semantics(mergeDescendants = true) {} to each timeline event container so TalkBack treats the date, title, and description as a single focusable unit — this mirrors the intended reading experience and avoids unnecessary swipe stops.
  • Set a contentDescription inside the semantics block that combines the date and event text (e.g. "March 2024, Project kickoff and requirements gathering") — this ensures TalkBack reads a coherent, complete sentence rather than fragmented sub-strings.
  • Connector lines and decorative dot nodes rendered as composables must use Modifier.semantics { invisibleToUser() } or be drawn via Canvas without semantics — they must not receive TalkBack focus.
  • If timeline events are expandable, set stateDescription = if (expanded) "Expanded" else "Collapsed" inside the semantics block and use a Role.Button on the tappable container so TalkBack announces both the action role and the current state on focus.

Example code

@Composable
fun TimelineEventRow(
    date: String,
    description: String
) {
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .semantics(mergeDescendants = true) {
                contentDescription = "$date, $description"
            }
            .padding(vertical = 8.dp),
        horizontalArrangement = Arrangement.Start
    ) {
        Column(
            horizontalAlignment = Alignment.CenterHorizontally,
            modifier = Modifier.width(24.dp)
        ) {
            Box(
                modifier = Modifier
                    .size(12.dp)
                    .background(Color.Blue, shape = CircleShape)
                    .semantics { invisibleToUser() }
            )
            Spacer(
                modifier = Modifier
                    .width(2.dp)
                    .weight(1f)
                    .background(Color.Gray.copy(alpha = 0.4f))
                    .semantics { invisibleToUser() }
            )
        }
        Column(modifier = Modifier.padding(start = 12.dp)) {
            Text(
                text = date,
                style = MaterialTheme.typography.labelSmall,
                color = MaterialTheme.colorScheme.onSurfaceVariant
            )
            Text(
                text = description,
                style = MaterialTheme.typography.bodyMedium
            )
        }
    }
}
