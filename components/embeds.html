Embeds (Maps, iFrames)

Accessible embedded content patterns including iframes, maps, and third-party widgets.

Design guidelines

UX guidelines

  • Always provide a non-embed alternative. Maps should be accompanied by a plain-text address and a visible link to an external map application. The alternative must be adjacent to the embed — not buried in a footer or tooltip.
  • Use a click-to-load pattern for performance. Replace the default embed markup with a <button> that inserts the iframe on interaction. This improves page load time, reduces tracking, and gives users an explicit control point.
  • Keep iframes within the viewport height. An iframe taller than the viewport forces users to scroll inside it, which is disorienting — especially for keyboard users who may become trapped inside.
  • Include a visible caption or title below the embed. A short sentence explaining the embed's purpose helps all users — particularly those on slow connections who may see the iframe before it fully renders.

Visual design guidelines

  • Show a visible loading state while the embed loads. Display a spinner or placeholder so users know something is happening and the page has not stalled.

Dev guidelines for web

  • Every <iframe> must have a descriptive title attribute. Screen readers announce the title when focus moves into the frame. Use a specific description — for example, title="Google Map showing our London office location" — not a generic title="Map".
  • Use the sandbox attribute where appropriate. Restricting iframe permissions with sandbox reduces the attack surface and prevents the embed from interfering with the parent page's focus management.
  • Ensure there is no keyboard trap. Users must be able to Tab out of the embed using Tab, Shift+Tab, or Escape. Test every third-party embed with keyboard-only navigation — embedded maps are frequent offenders.
  • For maps, provide an <a href> link to an external map app as the accessible alternative. The link must be in the DOM adjacent to the iframe, not inside it, so users who cannot interact with the map can still get directions.
  • Lazy-load iframes with a <button> trigger, not a <div>. A button is focusable and announced to screen readers. On activation, insert the <iframe> into the DOM and move focus to it programmatically.
  • Add loading="lazy" to <iframe> elements that are below the fold. This defers iframe loading until the user scrolls near them, improving initial page performance without sacrificing content availability.

Example code

<!-- Video embed with accessible title -->
<iframe
  src="https://www.youtube.com/embed/VIDEO_ID"
  title="Introduction to Web Accessibility (10 min)"
  width="560"
  height="315"
  allowfullscreen
  loading="lazy"
></iframe>

<!-- Fallback link for users who cannot access the embed -->
<p>
  <a
    href="https://www.youtube.com/watch?v=VIDEO_ID"
    target="_blank"
    rel="noopener"
  >
    Watch on YouTube: Introduction to Web Accessibility
    <span class="visually-hidden">(opens in new tab)</span>
  </a>
</p>

Dev guidelines for iOS

  • Give every WKWebView an accessible label. Apply .accessibilityLabel("...") to the WKWebView container so VoiceOver announces a meaningful description — for example, "Google Map showing our London office" — rather than reading out a raw URL or staying silent.
  • Provide a native fallback button adjacent to any embedded map. Place a clearly labelled Button immediately after the map view that opens the location in Maps.app via a deep link. Users who cannot interact with a map embed must still be able to get directions.
  • Mark decorative or purely visual embed containers as hidden from assistive technology. Use .accessibilityHidden(true) on any wrapper view that contains no interactive or informational content — for example, a loading placeholder — so VoiceOver skips it entirely.
  • Apply .accessibilityIgnoresInvertColors() to map and media embeds. Map tiles and video frames are meaningful visual content; inverting their colours makes them unusable. This modifier preserves their appearance when Smart Invert is active.
  • Post a VoiceOver announcement when the embed finishes loading. Use UIAccessibility.post(notification: .announcement, argument: "Map loaded") so users who cannot see the screen know when the content is ready to interact with.

Example code

import SwiftUI
import WebKit
import MapKit

struct LocationEmbedView: View {
    let coordinate = CLLocationCoordinate2D(latitude: 51.5074, longitude: -0.1278)
    let address = "123 Example Street, London, EC1A 1BB"

    var body: some View {
        VStack(alignment: .leading, spacing: 12) {
            Map(coordinateRegion: .constant(
                MKCoordinateRegion(
                    center: coordinate,
                    span: MKCoordinateSpan(latitudeDelta: 0.01, longitudeDelta: 0.01)
                )
            ))
            .frame(height: 240)
            .accessibilityLabel("Map showing our London office at \(address)")
            .accessibilityIgnoresInvertColors()

            Text(address)
                .font(.subheadline)

            Button("Open in Maps") {
                openInMaps()
            }
            .accessibilityHint("Opens the location in the Maps app")
        }
        .padding()
        .onAppear {
            UIAccessibility.post(
                notification: .announcement,
                argument: "Map loaded. Office location is displayed."
            )
        }
    }

    func openInMaps() {
        let url = URL(string: "maps://?q=\(address.addingPercentEncoding(withAllowedCharacters: .urlQueryAllowed) ?? "")")!
        UIApplication.shared.open(url)
    }
}

Dev guidelines for Android

  • Set a contentDescription on every WebView or map container. Use Modifier.semantics { contentDescription = "..." } so TalkBack announces a meaningful description rather than a raw URL or nothing at all.
  • Provide a native fallback button adjacent to any embedded map. Place a clearly labelled Button immediately after the map composable that opens the location in a maps app via an intent. Do not rely on users being able to interact with the WebView map.
  • Use Modifier.clearAndSetSemantics { } on loading placeholders. Placeholder composables shown while the embed loads carry no useful information; clearing their semantics prevents TalkBack from announcing them.
  • Announce when the embed finishes loading using LiveRegionMode.Polite. Set liveRegion = LiveRegionMode.Polite on a status text composable and update its value to "Map loaded" when the WebView finishes loading, so users relying on TalkBack know the content is ready.

Example code

import androidx.compose.foundation.layout.*
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.semantics.*
import androidx.compose.ui.unit.dp
import com.google.maps.android.compose.*

@Composable
fun LocationEmbedView(
    address: String = "123 Example Street, London, EC1A 1BB",
    onOpenInMaps: () -> Unit
) {
    var loadStatus by remember { mutableStateOf("") }

    Column(
        verticalArrangement = Arrangement.spacedBy(12.dp),
        modifier = Modifier.padding(16.dp)
    ) {
        GoogleMap(
            modifier = Modifier
                .fillMaxWidth()
                .height(240.dp)
                .semantics {
                    contentDescription = "Map showing our London office at $address"
                },
            onMapLoaded = {
                loadStatus = "Map loaded. Office location is displayed."
            }
        )

        Text(
            text = loadStatus,
            modifier = Modifier.semantics {
                liveRegion = LiveRegionMode.Polite
            }
        )

        Text(text = address)

        Button(
            onClick = onOpenInMaps,
            modifier = Modifier.semantics {
                contentDescription = "Open office location in Maps app"
            }
        ) {
            Text("Open in Maps")
        }
    }
}
