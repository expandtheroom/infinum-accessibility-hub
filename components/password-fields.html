Password Fields

Accessible password input patterns covering visibility toggles, error messaging, and screen reader support.

Design guidelines

UX guidelines

  • The show/hide toggle button must be adjacent to the password field with a clear icon (e.g. an eye or eye-slash) plus a visible or screen-reader-accessible text label. Place it consistently in the same position across all password fields in the product to build a predictable pattern.
  • Design password requirements as visible persistent text below the field (e.g. "At least 8 characters, one uppercase letter, one number"), not revealed only on error. This reduces cognitive load for all users and prevents frustrating trial-and-error.
  • Annotate the toggle button's accessible name in design files — specify that the text must change from "Show password" to "Hide password" (or equivalent) to reflect the current state, not just the icon.
  • Consistent toggle placement across all password fields — if the toggle appears inside the input on the right for the first field, it must appear in the same position for confirm-password and new-password fields. Inconsistency creates confusion, particularly for users with cognitive disabilities.

Visual design guidelines

  • Password strength meters must use color plus a text label — never color alone. Display labels such as "Weak", "Fair", "Strong", or "Very strong" alongside the visual bar or segmented indicator. A meter that only changes from red to green fails WCAG 1.4.1 (Use of Color).
  • Strength labels must be visible at all times the meter is displayed — not just on hover, not only announced to screen readers, but rendered as visible text adjacent to the strength bar.

Dev guidelines for web

  • Use <input type="password"> with a visible, associated <label> via for/id. Set autocomplete="current-password" on login forms and autocomplete="new-password" on registration and password-change forms — this allows password managers, which many users with cognitive or motor disabilities rely on, to fill credentials automatically.
  • The show/hide toggle must be a <button type="button"> with aria-pressed="false" (updated to aria-pressed="true" when password is visible). Toggle the input's type attribute between "password" and "text" to control visibility. Update the button's accessible label to reflect the available action: "Show password" or "Hide password".
  • Never block paste on password fields. Intercepting the paste event (e.g. onpaste="return false") is a WCAG 2.1 SC 1.3.5 failure and prevents password managers from filling credentials. Remove any paste-blocking handlers entirely.
  • Never set autocomplete="off" on login forms. This blocks password managers and browser autofill, which are essential assistive tools for users with memory, motor, or cognitive disabilities.
  • Announce strength changes via aria-live="polite": <p aria-live="polite" aria-atomic="true">Password strength: Strong</p>. Use aria-atomic="true" so the full message is announced on each change. Avoid aria-live="assertive" — it is too interruptive during active typing.
  • If the strength meter is a visual bar or segmented graphic, supplement it with a role="meter" element carrying aria-valuenow, aria-valuemin, aria-valuemax, and aria-valuetext (e.g. aria-valuetext="Strong") to expose the value programmatically to assistive technology.
  • Link password requirements to the input via aria-describedby so screen readers announce them when the field receives focus — users hear the requirements before they start typing, not just after a failed submission.

Example code

<div>
  <label for="password">
    Password
    <span aria-hidden="true">*</span>
    <span class="visually-hidden">(required)</span>
  </label>
  <div>
    <input
      type="password"
      id="password"
      name="password"
      required
      autocomplete="current-password"
      aria-describedby="password-hint"
    />
    <button
      type="button"
      aria-controls="password"
      aria-pressed="false"
      onclick="
        var i = document.getElementById('password');
        var p = this.getAttribute('aria-pressed') === 'true';
        i.type = p ? 'password' : 'text';
        this.setAttribute('aria-pressed', !p);
        this.textContent = p ? 'Show' : 'Hide';
      "
    >
      Show
    </button>
  </div>
  <p id="password-hint">Minimum 8 characters.</p>
</div>

Minimum 8 characters.

Dev guidelines for iOS

  • Use isSecureTextEntry on a UITextField (UIKit) or SecureField (SwiftUI) for the password field. Attach a visible label via .accessibilityLabel("Password") so VoiceOver announces the field name clearly, and link any requirement text with .accessibilityHint("Minimum 8 characters") to surface requirements without the user having to navigate away.
  • The show/hide toggle must carry a dynamic .accessibilityLabel that reflects the current action — "Show password" when the field is masked, "Hide password" when it is revealed. Update the label in the toggle action so VoiceOver always announces what will happen next, not what just happened.
  • Combine the password input and its toggle button using .accessibilityElement(children: .contain) on the enclosing container so that VoiceOver treats the input and button as separate, individually focusable elements. Do not use .combine, which would merge them into one element and make the toggle unreachable.
  • Announce password strength changes using UIAccessibility.post(notification: .announcement, argument: "Password strength: Strong"). Trigger this after a short debounce (e.g. 0.5 s) while the user types so that the announcement does not interrupt every keystroke. Avoid .screenChanged — it shifts focus away from the field.
  • Mark decorative strength bar segments with .accessibilityHidden(true) and expose strength only through the live announcement and a visible text label. This prevents VoiceOver from landing on meaningless graphical elements.

Example code

import SwiftUI

struct AccessiblePasswordField: View {
    @State private var password = ""
    @State private var isVisible = false

    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            Text("Password")
                .font(.callout)
                .fontWeight(.semibold)

            HStack(spacing: 0) {
                Group {
                    if isVisible {
                        TextField("Password", text: $password)
                    } else {
                        SecureField("Password", text: $password)
                    }
                }
                .textContentType(.password)
                .autocorrectionDisabled()
                .textInputAutocapitalization(.never)
                .padding(.horizontal, 12)
                .padding(.vertical, 10)

                Button {
                    isVisible.toggle()
                } label: {
                    Image(systemName: isVisible ? "eye.slash" : "eye")
                        .foregroundColor(.secondary)
                        .padding(.horizontal, 12)
                }
                .accessibilityLabel(isVisible ? "Hide password" : "Show password")
            }
            .overlay(
                RoundedRectangle(cornerRadius: 8)
                    .stroke(Color.gray.opacity(0.4), lineWidth: 1)
            )

            Text("Minimum 8 characters.")
                .font(.caption)
                .foregroundColor(.secondary)
                .accessibilityHidden(true)
        }
        .accessibilityElement(children: .contain)
    }
}

Dev guidelines for Android

  • Use PasswordVisualTransformation for the masked state and VisualTransformation.None for the revealed state. Set a contentDescription on the enclosing field via Modifier.semantics { contentDescription = "Password" } so TalkBack announces the field name correctly, since TextField labels are not always picked up reliably on all API levels.
  • The show/hide toggle button must update its contentDescription to match the available action — "Show password" when masked, "Hide password" when revealed. Use Modifier.semantics { contentDescription = if (isVisible) "Hide password" else "Show password" } on the IconButton.
  • Do not merge the password field and its toggle into a single focusable unit. Keep them as separate elements so TalkBack users can focus the toggle independently. Avoid wrapping the row in Modifier.semantics { mergeDescendants = true }.
  • Announce password strength changes using LiveRegionMode.Polite on the strength label: Modifier.semantics { liveRegion = LiveRegionMode.Polite }. Update the label text in state and Compose will dispatch the announcement automatically. Do not use Assertive, which interrupts TalkBack mid-sentence while the user is typing.

Example code

import androidx.compose.foundation.layout.*
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.Visibility
import androidx.compose.material.icons.filled.VisibilityOff
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.semantics.*
import androidx.compose.ui.text.input.*
import androidx.compose.ui.unit.dp

@Composable
fun AccessiblePasswordField() {
    var password by remember { mutableStateOf("") }
    var isVisible by remember { mutableStateOf(false) }

    Column(verticalArrangement = Arrangement.spacedBy(4.dp)) {
        OutlinedTextField(
            value = password,
            onValueChange = { password = it },
            label = { Text("Password") },
            visualTransformation = if (isVisible)
                VisualTransformation.None
            else
                PasswordVisualTransformation(),
            keyboardOptions = KeyboardOptions(
                keyboardType = KeyboardType.Password
            ),
            trailingIcon = {
                IconButton(
                    onClick = { isVisible = !isVisible },
                    modifier = Modifier.semantics {
                        contentDescription =
                            if (isVisible) "Hide password" else "Show password"
                    }
                ) {
                    Icon(
                        imageVector = if (isVisible)
                            Icons.Filled.VisibilityOff
                        else
                            Icons.Filled.Visibility,
                        contentDescription = null
                    )
                }
            },
            modifier = Modifier
                .fillMaxWidth()
                .semantics { contentDescription = "Password" }
        )
        Text(
            text = "Minimum 8 characters.",
            style = MaterialTheme.typography.bodySmall,
            color = MaterialTheme.colorScheme.onSurfaceVariant
        )
    }
}
